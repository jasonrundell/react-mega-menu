## Since 3.0.0-beta.0

`3.0.0-beta.0` is on npm under the `beta` dist-tag. `3.0.0-beta.1` (unpublished
as of this note) changes the shipped stylesheet and the token contract:

- The off-canvas nav and every mega / sub panel now paint their own chrome
  (`--rmm-panel-bg`, `--rmm-panel-border`, `--rmm-panel-shadow`,
  `--rmm-panel-padding`), the shell and panels have a gutter (`--rmm-gutter`),
  mega panels lay out as a grid of columns (`--rmm-column-min-width`), links
  hover as rounded pills (`--rmm-link-radius`) and chevrons are drawn in CSS
  (`--rmm-icon-stroke`). `--rmm-line-height` is new too.
- `--rmm-hamburger-top` and `--rmm-hamburger-left` are gone: the hamburger sits
  inline at the right of a single top bar, so `--rmm-menu-height` now defaults
  to `--rmm-topbar-height` instead of twice it.
- `slideDirection` now applies to the mega and sub panels as well as the nav, so
  every level of the mobile menu enters from the same side.
- Both demos install the beta.1 tarball; the Vite demo page was restyled.

Publish it the same way as beta.0 (the workflow derives the `beta` dist-tag from
the pre-release version), then re-verify both demos against the registry.

## Publish the beta

Publishing runs in GitHub Actions (`.github/workflows/npm-publish.yml`) with the
repository secret `npm_token`. On `main`, open the Actions tab, choose "Publish
to npm" and run it; the dist-tag is derived from the version (`3.0.0-beta.1`
publishes under `beta`). Publishing a GitHub Release triggers the same workflow.
To publish from a machine instead:

```sh
npm ci && npm test
npm publish --tag beta          # publishes 3.0.0-beta.1 under the "beta" dist-tag
```

Verify the published package (not the tarball) in both demos:

```sh
cd demo && npm install @jasonrundell/react-mega-menu@beta && npm run build && npm run dev
cd ../next-demo && npm install @jasonrundell/react-mega-menu@beta && npm run build && npm start
```

Walk both demos in a browser: four themes via `?theme=`, both `slideDirection`
values below the `large` breakpoint, keyboard rows 4 and 12 of the walkthrough
with a physical keyboard (those two could not be automated). Then restore the
`file:` tarball specs if you want the demos to keep installing from the repo.

## Ship 3.0.0

Release tags in this repo are unprefixed (`2.2.2`, not `v2.2.2`), so bypass
`npm version`'s default `v` prefix:

```sh
npm version 3.0.0 --no-git-tag-version   # bumps package.json / lockfile only
npm run pack:demo                        # refresh the committed tarball name for the demos
# update demo/package.json and next-demo/package.json to the 3.0.0 tarball, reinstall both
git commit -am "3.0.0" && git tag 3.0.0
git push && git push origin 3.0.0
# then run "Publish to npm" from the Actions tab (or publish a GitHub Release
# for the 3.0.0 tag); a non-pre-release version publishes under "latest"
```

The CommonJS entry ships as `dist/index.cjs` with its own `index.d.cts`, so
`require()` consumers resolve real CommonJS; publint and arethetypeswrong pass
for every resolution mode.
